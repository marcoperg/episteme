#+title: Episteme relations

* Purpose

This package is a rebuildable Ciao query layer over relations authored in
Episteme Org files. Org remains authoritative. The package stores each assertion
once and derives incoming navigation, semantic inverses, symmetric relations,
subproperties and explicitly enabled transitive closure.

The layer exists to answer concrete questions --- which notes use a source,
where a passage was cited, what relations leave a note, and what consequences
follow from an explicitly declared schema --- without turning generated Prolog
into another database that must be edited or synchronized by hand.

* Requirements and lifecycle

Run commands from the Episteme repository root. Generation needs Python 3;
queries need Ciao. The ignored =generated/relation_facts.pl= file is absent after
a fresh clone and is created by =bin/build-relations.py=. Both query wrappers
rebuild it automatically. Org edits never need a corresponding manual Prolog
edit or commit.

* Files

- =episteme_relations.pl= --- typed query API and inference rules.
- =relation_schema.pl= --- inverse, symmetric, transitive and subproperty
  declarations.
- =query_relations.pl= --- command-line adapter used by Emacs.
- =generated/relation_facts.pl= --- generated and ignored Ciao facts.
- =../bin/build-relations.py= --- Org-to-Ciao compiler frontend.
- =../bin/query-relations= --- rebuild-and-query wrapper.
- =../bin/relation-toplevel= --- rebuild-and-open interactive Ciao wrapper.
- =../lisp/episteme-citations.el= --- Emacs consumer of the query CLI.

* Data model

The generator emits identified assertions:

#+begin_src prolog
asserted(Id, Subject, Predicate, Object, Origin).
#+end_src

Current node forms are =note(Id)=, =source(CiteKey)=, and =context(Path)=.
=note(Id)= uses the note's file-level Org =:ID:=; origins independently retain
=org(Path, Line)=. Direct citations produce =cites= assertions, while file-level
=:RELATIONS:= entries produce their declared predicate.

For every graph-participating note, the generator also records identity/location
and the directory branch needed to classify it:

#+begin_src prolog
note_index(note(Id), Path, context(Directory)).
context_parent_index(context(Directory), context(Parent)).
#+end_src

The stable API exposes these as =note_path/2=, =primary_context/2=, and
=parent_context/2=. ID-bearing files without authored relations or citations are
outside this generated graph, as are unrelated directory branches. Structural
edges for participating notes also enter =relation/3=;
=contains_note= and =child_context= are their declared semantic inverses.

Each direct citation also produces an occurrence fact:

#+begin_src prolog
asserted_citation(Id, Note, Source, locator(Locator),
                  org(Path, Line, Column)).
#+end_src

=Locator= is the whitespace-normalized Org reference suffix, such as
=locator('p. 42')=, or =no_locator= when none was authored. Occurrences complement rather
than replace the graph-level =cites= assertion. They preserve repeated citations
of the same source within one note as independently navigable evidence.
Because graph assertions carry line but not column, repeated citations of the
same source on one line collapse to one =cites= assertion. Use the occurrence
API, not graph-fact counts, for exact evidence locations or citation frequency.

=note(Id)= is stable across a file move. =note_path/2= retains the complete
repository-relative navigation address, and =primary_context/2= records its
current parent directory. Moving a file therefore changes its path and structural
relations without changing the node. Generated relation and occurrence IDs also
include source position and are not stable external identifiers; authored Org
IDs and citekeys carry durable identity across rebuilds.

Generated physical indexes support efficient relation and citation lookup in
either direction. They do not constitute duplicate authored information.

* Query semantics

- =asserted_relation/5= returns exactly authored assertions with provenance.
- =citation_occurrence/5= returns authored citation occurrences with locators.
- =citations_from/4= and =citations_to/4= use the occurrence indexes.
- =note_path/2= maps a graph note's durable identity to its current file path.
- =primary_context/2= and =parent_context/2= query its generated directory branch.
- =immediate_relation/3= includes direct assertions and non-transitive schema
  consequences.
- =relation/3= additionally includes enabled transitive consequences.
- =outgoing/3= queries from subject to object.
- =incoming/3= queries the same predicate from object to subject.

Incoming navigation is not semantic inversion. For example, querying an
=informed_by= edge backwards retains that predicate, while the declaration
=inverse_relation(informed_by, informs)= derives a distinct =informs= edge.

Unknown predicates remain ordinary directed relations. Do not mark a predicate
symmetric or transitive merely to make navigation convenient.

The engine supports inverse, symmetric, transitive and subproperty declarations.
The current schema enables =informed_by=/=informs=, =cites=/=cited_by=,
=primary_context=/=contains_note=, and =parent_context=/=child_context= inverses.
No predicate is currently declared symmetric, transitive or a subproperty.

* Usage

Generate the fact module:

#+begin_src sh
bin/build-relations.py
#+end_src

List notes that cite or are informed by a source:

#+begin_src sh
bin/query-relations references muller\&vogelMullerVogelAtlas1995
#+end_src

The wrapper regenerates facts before querying, so interactive results follow the
current Org files. Its tab-separated rows contain predicate, path, line, column,
and locator; the final field is empty when no locator was authored. A relation
drawer assertion has no exact character position, so its reported column is the
synthetic value =1=. The Emacs =C-c B= command uses these rows from a generated Bibliotheca
item; it opens the only occurrence or prompts with every citation and
=informed-by= assertion referring to that source.

For exploratory queries, rebuild and open the stable API in a Ciao top level:

#+begin_src sh
bin/relation-toplevel
#+end_src

The launcher imports =relations/episteme_relations.pl=. Query
=asserted_relation/5= for authored graph facts, =citation_occurrence/5= for exact
passage references, or =incoming/3=, =outgoing/3=, and =relation/3= for semantic
traversal.

#+begin_src prolog
?- citations_to(source('sourceKey'), Note, Locator, Origin).

?- note_path(note(NoteId), Path).

?- primary_context(note(NoteId), Context).

?- asserted_relation(Id, note(NoteId), informed_by,
                     source('sourceKey'), Origin).

?- incoming(source('sourceKey'), Predicate, note(NoteId)).

?- outgoing(source('sourceKey'), informs, note(NoteId)).
#+end_src

The second query resolves stable identity to physical location, and the third
returns its current directory classification. The fourth returns only authored
facts and provenance. The fifth traverses authored direction backwards without
changing =Predicate=; the sixth asks for the separately declared semantic inverse
of =informed_by=.

* Verification

Run Python tests, generate facts, check the Ciao modules and run the end-to-end
query test:

#+begin_src sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
emacs --batch -Q -L lisp -l tests/episteme-citations-test.el \
  -f ert-run-tests-batch-and-exit
bin/build-relations.py
ciaopp -V relations/relation_schema.pl
ciaopp -V relations/episteme_relations.pl
#+end_src

The expected CiaoPP baseline is zero false assertions. =relation_schema.pl=
checks all current contracts. Analysis of =episteme_relations.pl= also reports
unverified contracts and unknown internal tabling predicates because the
analyzer does not model the tabled package completely; runtime semantics are
therefore sampled by =tests/check_relation_semantics.pl= through the Python
suite, including authored provenance, incoming traversal, semantic inversion and
citation lookup.

Ciao's tabled execution is used for cyclic schema and transitive queries. The
graph is finite and generated without term-building recursion, which keeps the
tabled relations finite.
