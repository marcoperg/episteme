#+title: Episteme

* Episteme

#+begin_quote
Epistēmē (ἐπιστήμη) is the Greek word for knowledge or understanding: the
theoretical, reasoned grasp of how and why things are. Aristotle contrasts it
with /praxis/ (action) and /technē/ (craft).
#+end_quote

Following the spirit of this word, this collection of org-roam notes on
different subjects forms my personal map of knowledge --- the theoretical half
of a pair whose practical counterpart lives in the =praxis= repo (possessions,
houses, trips, the logistics of daily life).

The specific selection of topics and the reason behind them may vary; usually I
write about what I want to understand deeper, either the topic itself or its
connections to things in another subject.

* Design principles

- *Authored text is authoritative.* Notes, citations and =:RELATIONS:= drawers
  are the source of truth. Generated indexes may always be deleted and rebuilt.
- *The tree gives primary context.* Directory placement answers where a note
  principally belongs; the generated graph represents that placement as
  =primary_context= and =parent_context= relations. Links and authored relations
  express connections that cross the tree.
- *Identity and location are distinct.* A graph-participating note is identified
  by its file-level Org =:ID:=. Its repository-relative path remains its current
  location, navigation address, and source of directory classification.
- *Bibliographic identity comes from Bibliotheca.* Stable Better BibTeX citekeys
  connect notes to the sibling Zotero mirror without creating metadata-only
  source notes in Episteme. Once used, a key should be pinned in Better BibTeX;
  an intentional rename must update both catalogues and every Episteme use in
  one checked change.
- *Provenance has two levels.* =informed-by= records broad intellectual
  influence on a note. A direct citation records evidence for a particular
  claim or quotation and may carry a passage locator.
- *Semantics are explicit.* Ciao derives only declared inverses, symmetry,
  subproperties and transitivity. Reverse navigation alone never changes the
  meaning of a predicate.

* Requirements and layout

Episteme is normally checked out as =~/knowledge/episteme= beside
=~/knowledge/bibliotheca=. The sibling bibliography is optional for parsing but
required to validate citekeys and use the full citation workflow.

- Python 3 is required for integrity checks and fact generation; no third-party
  Python packages are used.
- Ciao is required for semantic queries and =bin/relation-toplevel=.
- Emacs with Org and Citar is optional, but provides citation insertion and
  bidirectional navigation.
- Org-roam is optional and supplies note discovery and durable ID links.

* Structure

The directory tree is the primary organizational structure. It gives every note
a canonical home and records its main context: broad domain, subject, course,
source, period, author, or another useful hierarchy. Different parts of the tree
therefore express different kinds of organization; being below a directory does
not automatically make a note an ontological instance of every ancestor.

The main domains include =math/=, =physics/=, =philosophy/=, =ml/=,
=linguistics/=, =languages/=, =telecom/=, =GIICC/=, =Libros/=, =Museos/=,
=meditation/=, and =audiovisual/=. Deeper directories are intentional when they
preserve meaningful subject, curriculum, source, or geographic context.

Org IDs and links complement this tree rather than replace it:

- A directory records a note's primary context.
- An =:ID:= gives a note or heading a persistent address. It does not by itself
  declare an ontology entity.
- An =id:= link records a durable relation that crosses the directory tree or
  should survive a file move.
- A =:ROAM_ALIASES:= property records alternative names for an addressable note.
  Aliases aid lookup and link insertion; they do not create additional nodes or
  ontological relations. Values containing spaces are quoted, for example
  =:ROAM_ALIASES: "RL" "reinforcement learning"=.
- A relative =file:= link is suitable for local structural relationships whose
  path is itself useful context.
- Citations record bibliographic provenance; they are not substitutes for note
  identity or conceptual links.

A file-level =:RELATIONS:= drawer records explicit typed relations whose subject
is the current note's durable =:ID:=. Place it before the first heading. The
first supported predicate is =informed-by=:

#+begin_src org
:PROPERTIES:
:ID:       01234567-89AB-CDEF-0123-456789ABCDEF
:END:
#+title: Example note

:RELATIONS:
- informed-by :: [cite:@langAlgebra2002]
:END:
#+end_src

This means that the note's content or the author's understanding was
meaningfully informed by that source. It does not claim that the source is
primary, that every statement derives from it, or that it supports every claim.
Use one item per source and keep qualifications in the note's prose. Specific
claims and quotations should still receive direct citations. No date is stored
in the relation; Git records when it is introduced, changed, or removed. Use
=C-c b= after the =::= to select its citation with Citar.

Passage-level citations support particular claims and quotations. Put the
citation immediately after the material it supports and include the most stable
available locator:

#+begin_src org
This construction appears in the third millennium BCE [cite:@sourceKey p. 42].

#+begin_quote
Exact quoted passage.
#+end_quote
[cite:@sourceKey pp. 42-43]
#+end_src

Use =p.= or =pp.= for pages, =chap.= for chapters, =sec.= for sections, =fig.=
for figures, and =HH:MM:SS= for audiovisual timestamps. A stable named section
is appropriate when pagination is unavailable. A locator is not required when a
citation genuinely refers to the whole work. The locator's wording is preserved
without semantic interpretation, but runs of whitespace are normalized for
deterministic storage and display.

File-level IDs are required for notes explicitly used as ontology or research
nodes, notes exported to another system, targets of durable semantic links, and
any file containing a direct citation or =:RELATIONS:= entry. Those authored
facts make the file a relation-graph node, so generation refuses to identify it
by a mutable path. IDs remain optional for course notes, reading extracts,
outlines, and other material that does not participate in the graph. A note can
be promoted later by assigning an ID when it first becomes meaningful there.

=:ROAM_ALIASES:= is the canonical alias representation. Obsidian/YAML forms such
as =aliases: - first name - second name= are migration artifacts and are not
interpreted as Org metadata.

This produces a tree plus graph: the tree supplies canonical context, while IDs
and links express relationships that cannot be represented by a single parent
directory. Notes should not be duplicated across directories merely to express
multiple classifications.

* Relation queries

The =relations/= Ciao package provides a rebuildable query layer over explicit
=:RELATIONS:= entries and direct Org citations. Org files remain authoritative;
=bin/build-relations.py= parses them through the integrity checker's shared
parser and writes an ignored =relations/generated/relation_facts.pl= module.

#+begin_example
Org notes
   -> bin/check-integrity.py shared parser
   -> bin/build-relations.py
   -> relations/generated/relation_facts.pl
   -> relations/episteme_relations.pl
   -> Ciao top level, CLI and Emacs
#+end_example

The generated Ciao module is deliberately not committed. After a fresh clone,
build it explicitly or invoke a wrapper that builds it first:

The stable API in =relations/episteme_relations.pl= supports authored facts with
provenance, individual citation occurrences with locators, incoming and outgoing
traversal, semantic inverses, subproperties, symmetric predicates, and explicitly
enabled transitive predicates. It also maps stable =note(ID)= nodes to their
current paths and derives =primary_context= and =parent_context= from directory
placement. Incoming traversal does not change a predicate:
traversing an =informed_by= assertion backwards is distinct from deriving its
semantic inverse, =informs=.

#+begin_src sh
bin/build-relations.py
bin/query-relations references muller\&vogelMullerVogelAtlas1995
bin/relation-toplevel
#+end_src

=bin/query-relations= and =bin/relation-toplevel= always rebuild before loading
the Ciao API, so they cannot silently query a stale snapshot. Generation runs
the full repository integrity checker first and refuses malformed relations,
broken links, or unresolved citekeys.

See [[file:relations/README.org][=relations/README.org=]] for the data model, API, schema policy, and
verification commands.

* Support files

- =bin/check-integrity.py= --- validates duplicate IDs, unresolved =id:= links,
  relative =file:= links, =SETUPFILE= paths, property and relations drawers,
  graph-node IDs, alias syntax, and all citation keys when Bibliotheca is
  available. Its parser
  also exposes direct citation locators and exact positions to the relation
  generator.
  Missing IDs outside the relation graph and deep directory structures are
  intentionally allowed. Run it
  together with its standard-library tests using:
  #+begin_src sh
  PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
  emacs --batch -Q -L lisp -l tests/episteme-citations-test.el \
    -f ert-run-tests-batch-and-exit
  bin/check-integrity.py
  bin/build-relations.py
  ciaopp -V relations/relation_schema.pl
  ciaopp -V relations/episteme_relations.pl
  #+end_src
- =setup.org= --- shared LaTeX preamble (theorem environments, packages),
  pulled into math/physics notes via =#+SETUPFILE: ../setup.org=.
- =../bibliotheca/zotero-library.bib= --- full Better BibTeX bibliography used
  by Org Cite and Citar. If a source needs substantive commentary beyond its
  catalogue metadata, write a normal contextual Episteme note and cite it there.
- =.attachments/= --- images embedded in notes (linked with =[[file:...]]=).

* Emacs

=lisp/episteme-citations.el= owns the knowledge-system behavior because it
consumes Episteme's CLI contract. Personal package choices and keybindings remain
in dotfiles. A minimal setup is:

#+begin_src emacs-lisp
(setq org-roam-directory (file-truename "~/knowledge/episteme")
      org-cite-global-bibliography
      (list (expand-file-name
             "~/knowledge/bibliotheca/zotero-library.bib")))

(add-to-list 'load-path
             (expand-file-name "~/knowledge/episteme/lisp"))
(require 'citar)
(require 'episteme-citations)

(setq org-cite-insert-processor 'citar
      org-cite-follow-processor 'citar
      org-cite-activate-processor 'citar
      citar-bibliography org-cite-global-bibliography
      citar-open-entry-function #'episteme-open-bibliotheca-entry)

(global-set-key (kbd "C-c B") #'episteme-citation-dwim)
(define-key org-mode-map (kbd "C-c b") #'org-cite-insert)
#+end_src

=C-c b= inserts a citation with Citar. =C-c B= opens the citation at point in
the generated Bibliotheca catalogue; in a Bibliotheca item it queries the Ciao
index and opens an exact referencing occurrence. The prompt includes predicate,
locator, line and column, and repeated citations in one note remain separate.

The package variables =episteme-directory=, =episteme-bibliotheca-file= and
=episteme-relation-query= can be customized when the repositories do not use the
default =~/knowledge= layout.
