Key exchange establishes a common secret over public communication without an
initial shared secret. Anonymous exchange against passive observation is weaker
than authenticated exchange of an indistinguishable session key.

* Setting and correctness

Alice and Bob begin without correlated secret information. They use independent
random coins and exchange public messages according to protocol \(\mathcal P\).
Let \(T_{\mathcal P}\) be its ordered transcript and let \(K_A,K_B\) be
their outputs. Perfect correctness requires \(\Pr[K_A=K_B]=1\) in an honest
execution. Write \(K\) for their common value
[cite:@fioreCryptographicProtocolosApplicatons sec. 7.2].

* Passive full-key recovery

Run the honest protocol, give its transcript and all public parameters to a
PPT adversary \(A\), and ask it to output \(\widehat K\). Define
\(\operatorname{KEAdv}[A,\mathcal P]=\Pr[\widehat K=K]\).

Recovery security means negligible success for every such adversary. This is a
success probability, not a distinguishing advantage. Even uniform guessing must
be negligible for a secure key-space family.

The observer may not alter, suppress, or inject messages. Identities are not
authenticated; correctness only concerns the honest execution. The experiment
does not describe an active network attacker.

* An unrecoverable secret need not look random

A stronger passive objective compares

\[
(T_{\mathcal P},K)
\quad\text{with}\quad
(T_{\mathcal P},U_{\mathcal K}),
\]

where \(U_{\mathcal K}\) is independent uniform in the same key space.
If that space depends on public parameters, sample the ideal key conditionally
from the corresponding space.

Full-key recovery security alone permits leakage of some key bits. It can even
permit an efficient test of whether a /supplied candidate/ equals the secret,
without giving a method to find that secret. Thus proving recovery resistance
does not justify treating the output as a fresh uniform symmetric key
[cite:@fioreCryptographicProtocolosApplicatons sec. 7.2.1].

* Public-key tasks and authentication

Public-key cryptography also includes encryption under a published key and
signatures with public verification: neither follows from a key-recovery theorem.

Active key substitution can expose a peer's secret. Binding public information
to identities needs additional mechanisms. A MAC already assumes a shared
authentication key, so does not remove this initial-key problem
[cite:@fioreCryptographicProtocolosApplicatons sec. 7.1].
